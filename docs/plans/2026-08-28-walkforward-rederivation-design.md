## 1. 问题：现在的阈值是拍脑袋的，而数据第一次够格说话

19 个策略档的检测参数（`minWallets` / `minPerWalletUsd` / score 下限 /
`maxPrice` / `freshSec` / `maxEntryDeviationCents` / 退出规则…）全部是设计
时的直觉初值。8-18 的 edge 体检已经证明当时**没资格**校准它们：可用数据仅
10 个交易日、断更 43 天、60 个分组零显著。现在情况变了：

- **30 个不间断日**（07-28 → 08-26）的干净窗口；
- **~2,769 笔已结算纸面仓**，每笔带完整不可变事实：`formation_ts` /
  `formation_price`（防前视锚，`atOrBefore` 语义）、`entry_price` /
  `exec_price` / `exec_best_ask`（CLOB 盘口快照真实执行）、`fee_usd`、
  `markout_30m/2h`、`realized_pnl`；
- **九规则退出网格已离线跑完**（`position_exit_sims`：每仓 × 9 条 TP/SL/限时
  规则的反事实盈亏，基于已结算仓不可变价格路径）。

## 2. 两条结构性约束（整个设计围绕它们成立）

### 2.1 可观测锥：只能收紧，不能放松

本系统**刻意不归档原始成交流**（总纲 §9 红线）。持久化的是「在当前阈值下
触发过的事实」：alerts、strategy_signals、follow_positions。这意味着：

- **收紧方向可回放**：比「当前阈值更严」的变体，其会触发的信号是现有信号的
  **子集**——逐仓事实全在库里，零推测。
- **放松方向不可回放**：$50k 以下的巨鲸单、2 钱包以下的共识组从未落库，
  「假如阈值更松」没有数据基础，任何外推都是编造。

结论：**本批只做收紧/平移方向的网格；放松方向的唯一诚实做法是开一个更松的
新档从今天起向前跑**（champion/challenger，见 §6）。报告必须自带这条声明。

### 2.2 永不改动存量档的参数：战绩完整性高于一切

档位参数一旦运行就是其公开战绩的定义。改参数=让历史净值曲线指向
另一个策略——这正是公开记分卡最不能犯的「社会证明造假软形态」。因此：

- **重推的产出不是「改参数」，而是「建议 + 新挑战者档」**（总纲 §P2.3 红线
  「阈值建议只作为可解释建议，不自动修改生产规则」的落地形态）；
- 胜出变体作为**新档**入种子（v5，`code` 加后缀如 `mega_whale_t26`），与
  原档并跑对照——这套机制反向对照档（seed v4）已经趟熟；
- 原档去留（继续跑 / 关推送）是运营者在 /manage 的手动决定。

## 3. 方案对比

| 方案                           | 做法                                                                | 裁决                                                                                          |
| ------------------------------ | ------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| A. 全量重模拟                  | 归档原始流,任意参数重放开仓                                         | **否**：流没存过；补归档违反总纲红线,且从今天存也要再等 30 天                                 |
| B. 网格 × 子集选择（**选定**） | 每个候选变体 = 对现有已结算仓/信号做**过滤器子集**,指标在子集上重算 | 每一行都是真实发生过的执行(含真滑点真手续费),零前视零执行猜测;天然限于收紧方向(§2.1,如实声明) |
| C. 只做在线 A/B                | 每个候选开新档向前跑                                                | 组合爆炸(每变体再等 30 天);但作为 B 的**验证末级**保留:离线胜出者才配上线当挑战者             |

方案 B 的关键简化：**入场变体 = 子集选择，退出变体 = 查表**。
`position_exit_sims` 已存每仓 × 9 退出规则的反事实盈亏，入场子集 × 退出规则
的二维网格是「子集里逐仓查表求和」，不产生任何新模拟。

## 4. 方法论（统计纪律 = edge-audit 三件套 + 两件新的）

### 4.1 Walk-forward 切分

- **按 UTC 周切折**：30 天干净窗 ≈ 4 个整周（07-28 起恰为周一，天然对齐
  `utcWeekStart`）。扩张窗：train=[W1] → validate=W2；train=[W1,W2] →
  validate=W3；train=[W1..W3] → validate=W4。闸门前的旧数据（部分档 8-13
  才出生）只并入 train，永不做 validate。
- **归折口径**：一笔仓按 `formation_ts` 归折（决策时刻，不是结算时刻——
  按结算归折会把训练期的决策泄进验证期）。
- **选择与评价严格分离**：train 段只做变体排序，validate 段只算成绩；
  任何在 validate 上回头调参的行为都等于把 OOS 烧掉。

### 4.2 指标（与全站同口径，不发明新的）

主指标 = **费用后、入场赔率调整的超额**（`gradeRows` 同族口径：excess vs
市场隐含），辅以结算 ROI、最大回撤、`markout_30m/2h`（形成价锚）。执行成本
不建模——`exec_price`/`fee_usd` 是逐仓已知事实。

### 4.3 显著性三道闸（缺一道结论就可能翻向，体检实证过）

1. **市场聚类 CI**（`clusteredInterval`）：同市场多仓 = 一次随机事件的
   副本，有效 n = 去重市场数。8-18 教训 + 校准页刚又实证过（8 观察 1 市场
   → 区间 21–100%）。
2. **Bonferroni 按声明的网格总数**：edge-audit 的纪律原样搬——网格里每个
   (档 × 变体) 都计入分母，跑得越多单个「显著」越不值钱；网格总数写死成
   脚本顶部常量，加维度必须同步更新。
3. **方向随机化 10,000 次**（Gómez-Cram 方法，生态调研标记为可抄）：对
   validate 段子集，把每仓方向按市场隐含概率随机重掷 10,000 次，变体真实
   超额在 null 分布中的分位即 p 值。这道闸专治「子集选择把运气选出来」——
   原论文里原始赢家只有 12% 通过。

### 4.4 最小样本闸门

- 变体在**每个 validate 折**内已结算仓 < 10 或去重市场 < 5 → 该折记
  「样本不足」，不参与该变体评分；
- 变体的有效 validate 折 < 2 → 变体整体只进「观察名单」，不进建议；
- 薄档（表 §1 右列）整档跳过网格，报告только各自的聚类 CI 现状——
  「数据不够」是结论，不是障碍。

## 5. 网格空间（v1，收紧/平移方向）

按检测器族定义，变体总数刻意压小（Bonferroni 分母就是它）：

| 族                       | 维度            | 取值（含当前值作对照基线）                                 |
| ------------------------ | --------------- | ---------------------------------------------------------- |
| heavy（巨鲸系）          | 单笔下限        | 当前 / ×1.5 / ×2                                           |
|                          | maxPrice        | 0.95（当前）/ 0.90 / 0.85                                  |
|                          | 形成偏离护栏 ¢  | 10（当前）/ 6 / 4                                          |
| consensus 系             | minWallets      | 当前 / +1                                                  |
|                          | minPerWalletUsd | 当前 / ×1.5 / ×2                                           |
|                          | freshSec        | 900（当前）/ 600 / 300                                     |
| lopsided/resolved        | tiltPct 下限    | 当前 / +0.1                                                |
| early_winner / lone_wolf | score 下限      | 当前 / +5 / +10                                            |
| 全族横切                 | 退出规则        | hold（当前）× `position_exit_sims` 九规则查表              |
| 全族横切                 | 赛道限定        | 全部（当前）/ 仅体育 / 仅非体育（edge 矩阵已示体育集中度） |

估算网格：≈ 13 个可重推档 × 每档 ≤ 24 个入场变体 × 10 退出 ≈ 上限 3,000 格，
其中绝大多数因最小样本闸门自动出局；Bonferroni 分母取**实际评过分的格数**
（脚本如实统计并打印）。

**刻意不进网格**：sizeUsd（仓位大小不改变信号质量，只改变方差）；reverse
翻边（反向档已在跑，是在线对照不是离线格）；任何放松方向（§2.1）。

## 6. 落地形态

### 6.1 `scripts/walkforward.ts`（edge-audit 的姊妹脚本）

- `npx tsx scripts/walkforward.ts [dbPath]`，只读库、零上游、可重跑幂等；
- 输出：终端人读报告 + 一行写入新表
  `walkforward_reports (id, created_at, window_from, window_to, grid_size,
config_json, report_json)`——报告是数据，进库不进 git；
- 报告结构（每个可重推档）：当前参数的 OOS 成绩（基线）→ 通过三道闸的
  变体列表（参数差异 / 各折 OOS 超额 ± 聚类 CI / 随机化 p / Bonferroni 后
  是否存活）→ 明确的「无变体存活」也是一等结论；
- 与 edge-audit 同款自述头：三层校正声明、网格总数、可观测锥声明。

### 6.2 /manage 报告区（新「🧪 阈值重推」卡）

最新一次报告的摘要（跑于何时 / 窗口 / 网格数 / 各档结论一行）+「按报告
开挑战者档」的操作入口**不做自动化**——v1 只展示,建档仍走既有 /manage
档位管理手工路径（运营者复制建议参数）。manage-sync 纪律：能力可达即可，
一键化留给验证过报告价值之后。

### 6.3 挑战者档上线路径（重推的「应用」）

1. 运营者从报告挑 ≤3 个存活变体（贪多=把 Bonferroni 白算了）；
2. 手工建档（名称含 `·t26` 类标记，`code` 后缀化，seed 不 bump——手工档
   本就允许）；`push_enabled` 保持关：挑战者先静默跑；
3. 跑满一个月后由**同一脚本**的下次运行评判 champion vs challenger——
   walk-forward 从一次性动作变成月度节律（cron 化留 v2，先手动跑）。

## 7. 诚实红线（写进报告模板的固定段落）

- **幸存者宇宙声明**：分析宇宙 = 在当前阈值下触发过的信号；对「从未触发过
  的世界」本报告一无所知。
- **收紧外推禁令**：任何变体的建议范围以其子集样本为界，禁止外推到放松方向。
- 每个数字必须同时携带：成熟样本数 / 去重市场数 / 聚类 CI / 随机化 p /
  参与 Bonferroni 的格数（总纲 §3.2 的展示纪律）。
- 报告不输出「买/卖建议」，只输出「参数变体在历史子集上的费用后超额」。

## 8. 明确不做（v1）

- 自动修改任何存量档参数（§2.2，永久红线不止 v1）；
- 放松方向的模拟（§2.1，改用挑战者档向前跑）；
- ML/黑箱调参（总纲 §9：可解释分量之外的东西一概不进）；
- 告警引擎（Telegram 噪声闸）的阈值——那套服务于「读者打扰成本」，目标
  函数不同，另立批次；
- cron 自动月跑与报告推送（先手动跑两次证明报告有用）。

## 9. 验收

- 单元：折切分（周对齐/formation_ts 归折/旧数据只进 train）、子集过滤器
  逐族（收紧语义）、退出查表合成、三道闸各自的红绿样例（构造已知答案的
  合成仓集）、最小样本闸门、Bonferroni 分母计数。
- 反事实校验：把随机化次数降到 100 跑合成数据，已知无 edge 的均匀集必须
  ~5% 假阳率；已知强 edge 的构造集必须存活。
- 真机：对生产库副本（每日快照）完整跑一轮，人工核对 2-3 个厚档的子集
  样本数与 /follow 页口径一致；报告落库、/manage 卡渲染。
