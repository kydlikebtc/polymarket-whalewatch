# 反向对照策略（负 EV 档的镜像档）设计

日期:2026-08-13
背景:策略中心 13 档上线后,线上真实数据显示多档胜率极低且 ROI 深度为负。
用户指令:「给胜率极低和负 EV 明显的策略都加上反向对照策略,一起持续观察」。

## 1. 线上数据与选档

2026-08-13 线上快照(结算净值 / ROI / 胜率(结算数)):

| 档           | 净值    | ROI    | 胜率      | 处置                                                   |
| ------------ | ------- | ------ | --------- | ------------------------------------------------------ |
| 巨鲸         | −$3,217 | −33.9% | 37% (19)  | ✅ 配「反巨鲸」                                        |
| 超级巨鲸     | −$744   | −29.8% | 40% (5)   | ✅ 配「反超级巨鲸」(样本未达线,前瞻对照)               |

选档线:**负 EV 明显(ROI ≤ −15%)或胜率 ≤ 40%**;「都加上」按字面执行,样本
< 10 的档也配 —— 反向档是前瞻性观察工具,信号逐笔与正向档配对,早跑早攒样本,
成本只是一行种子。样本达线(≥10 结算)与未达线的档在本表分开标注,读战绩时
区别对待。**逆势少数边 +38.9% / 72% 胜率本身就是「反向对照有效」的第一个实证**,
本设计是把这个已被验证的模式推广到其余负 EV 档。

## 2. 方案对比

**A. 逐 detector 加翻边参数**(照抄 lopsided 的 `side:"minor"` 模式)
— 否。lopsided 能翻边是因为分歧分析天然算出了两边的 outcome/asset;heavy/
resolved/lone_wolf/early_winner 的候选只带自己一边的 token,detector 是纯函数
(DetectorCtx 无 DB、无 meta),检测时刻拿不到对面 token id。硬做要么给 ctx 预
喂全市场 meta(多一轮上游预取、重构取数顺序),要么逐个 detector 改一遍且将来
每加一个反向档再改一遍。

**B. 通用 reverse 变换(选定)**
`StrategyParams.reverse?: boolean` + 开仓循环里的纯函数翻转 + `MarketMeta.clobTokenIds`。

- meta 恰好在开仓循环之前已按候选取好(翻转不改 conditionId,metaCids 覆盖天然成立);
- 一个纯函数 `reverseCandidate` 可单测;开仓循环只加一小段;护栏/执行层/结算/
  markout 全部零改动(翻转发生在候选层,下游只认候选字段);
- 对任意 source 通用:今天 6 档,将来再加反向档 = 只加种子行。

**C. 影子结算**(不真开反向仓,结算时对正向仓算 1−exit 的镜像盈亏)
— 否。对面价 ≠ 1−本方价(有价差),没有自己的 entry/执行层归因/UI 档位,
不满足「一起持续观察」;也破坏「一档 = 一行 follow_strategies」的架构。

## 3. 翻转语义(reverseCandidate 纯函数)

输入:正向候选 c + 该市场 MarketMeta。输出:翻转后的候选,或带原因的弃权。

- `outcomeIndex` → `1 − c.outcomeIndex`;`outcome`/`asset` → meta 的
  `outcomes[flipped]` / `clobTokenIds[flipped]`。
- `referencePrice` → `1 − c.referencePrice`:被反向信号的**镜像成本基准**。
  追价成本(positionSlippage)与护栏回退基准的语义随之成立:巨鲸 0.60 买 Yes,
  我们的对面基准是 0.40 买 No,进场比 0.40 贵多少就是我们的追价成本。
  落库后 `smart_avg_price` 列存的即是这个镜像基准。
- `formationTs` **不变**:与 lopsided「formationTs 恒取 sides[0]」同一论证 ——
  两档必须在同一时刻、以同一笔钱开仓,对照才成立;翻转不引入「择时不同」变量。
- `sourceKind`/`walletCount`/`totalNetUsd`/`title` 等归因字段不变(归因的是被
  反向的那个信号)。
- **fail-closed 弃权**(返回原因,call site 落日志):meta 缺失;`outcomes`/
  `clobTokenIds` 非双元素(3-way 市场「买对面」不良定义 —— sourceResolved 注释
  实证 3-way 真实存在);`clobTokenIds[c.outcomeIndex] !== c.asset`(gamma 元数据
  与成交流的 index 对齐被破坏,翻错边比不开仓危险得多);镜像 referencePrice
  越出 (0,1)。

## 4. 对照的对称性与已知不对称

两档 params 的检测字段逐字节相同 → detector 产出**完全相同的候选集**(纯函数,
同 trades/ctx/params)。分叉只发生在开仓侧,且规则对称:

- 各自过自己的 maxPrice(默认 0.95):正向档拦「买在 >0.95」,反向档拦「对面
  > 0.95」(即正向 <0.05 的极端低价信号)。两侧样本在各自价格尾部有截断,规则
  > 本身对称 —— 这是既有全局护栏哲学(拦结算清扫单)的自然延伸,不为反向档开洞。
- 各自过自己的偏离护栏:基准 = 各自 asset 在同一 formationTs 的形成价
  (fetchFormationPrice),回退到各自的 referencePrice(互为镜像)。
- 各自取各自 asset 的现价/盘口/markout —— 反向档的执行层归因(exec_*)与
  协议费按对面盘口/价格如实建模,不做 1−p 近似。
- 已知不对称:某一侧因取价失败/护栏拦截而单边弃权时,两档样本出现单笔错位
  (逆势少数边 18 vs 一边倒分歧 27 的既有现象同源)。对照按「同信号同时刻」
  配对,不按「同成交」配对 —— 与既有对照组口径一致。

## 5. 数据层改动

1. **MarketMeta.clobTokenIds: string[]**(必填):gamma /markets 同一响应里
   现成的字段(stringified JSON 数组,与 outcomes 对齐),normalize 里
   `jsonArr(...).map(String)`,零额外上游调用(与 fees 四件套同一论证)。
   **META_V 2 → 3**:closed 行缓存永不过期,不 bump 新字段在老行上永远缺失
   (META_V 注释里写明的既定规则)。
2. **种子 v3 → v4**:同一 if 块整体加宽(`!== "4"`),只 INSERT 6 条新档,
   既有 13 条逐字节不动(红线延续)。新档 params = 对应正向档逐字节 + `reverse: true`:

   | 新档       | source                 | 镜像自       |
   | ---------- | ---------------------- | ------------ |
   | 反巨鲸     | heavy(50k)             | 巨鲸         |
   | 反超级巨鲸 | heavy(150k)            | 超级巨鲸     |
   | 反巨鲸精英 | heavy(50k+score80)     | 巨鲸精英     |
   | 反分歧解除 | resolved               | 分歧解除     |
   | 反高分独狼 | lone_wolf(score90+10k) | 高分独狼     |
   | 反早期赢家 | early_winner(5k)       | 早期赢家跟投 |

3. **parseStrategy / parseParamsView**:`reverse` 按 side 同一套纪律 —— 显式
   布尔生效、缺失静默退 false、存在但非布尔留痕退 false。两侧默认永远一致。
4. **runFollowCycle 开仓循环**:候选进入既有守卫链之前,`s.reverse` 时先过
   `reverseCandidate`,弃权即 continue + 日志(带 strategy id/cid/原因)。
   查重(UNIQUE 三元组)用翻转后的 outcome —— 反向档有自己的 strategy_id,
   与正向档互不干扰。

## 6. 展示层改动

- `familyOf` 不变:反向档随其 source 归族(反巨鲸×3 → 异常大额;反分歧解除 →
  分歧;反高分独狼/反早期赢家 → 钱包画像),与正向档同屏相邻,像逆势少数边
  与一边倒分歧一样并排可比。
- 名字旁加 `反向对照` Tag(卡片 + 列表两处),sourceCoreHint 前缀「反向对照 ·」
  并注明「信号触发时买对面」。
- FAMILY_META 三族 blurb 各补一句对照读法(照抄分歧族为逆势少数边补第二句的
  先例:对照说明放族说明里)。
- STRATEGY_EMOJI 6 个新映射(与正向档成对的反语义):反巨鲸 🪝(钩那头 🐳)、
  反超级巨鲸 ⚓(压住 🌊)、反巨鲸精英 🎣(钓 🦈)、反分歧解除 🏴(🏳️ 的反面)、
  反高分独狼 🐑(🐺 的对面)、反早期赢家 🍂(🌱 的反面)。均核实无撞车。
- 净值曲线零改动:19 档 < 26 组合容量;全量显示时反向档自然落进虚线区
  (第 14 条起色相回用 + 虚线),筛选后下标漂移属既有已文档化行为。

## 7. 不做什么

- 不给正向档改任何参数/字段(战绩红线);不做历史回填 —— 反向档从上线时刻
  起新开仓,「持续观察」向前看;伪造历史 entry(没有当时的对面盘口)违背
  执行层建模的诚实纪律。
- 不为 3-way 市场定义「反向」;不给一边倒分歧再建第二个对照。
- 不改 follow_positions 表结构(smart_avg_price 复用为镜像基准,见 §3)。
