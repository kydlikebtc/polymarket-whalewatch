Polymarket 上的巨鲸很少自报家门。他们把大仓拆成许多小单、用新建的钱包、在赔率有利时进场。**WhaleWatch 要抓的正是这些**——一个把大单在几秒内推到 Telegram 的常驻 worker，一个用来挖掘单笔告警看不见的模式的网页看板，以及一份公开记分的纸面台账。

> ⚠️ **仅为研究与监控工具。** 全程只读 Polymarket **公开**数据——无鉴权、无密钥、不交易、不托管任何资金。文中一切不构成投资建议。把任何信号当作可交易之前，请先读[我们到底知道什么](#-我们到底知道什么以及不知道什么)。

## 🚀 具体做什么

### 第一层 —— 把洪流变得可检索

- **24h 扫描器**（`/`）——滚动窗口内的每一笔大额成交。可按**金额**、**买卖方向**、**时间窗**（1h/6h/24h）、**价格带**（赔率）、**地址年龄**、**赛道分类**（体育细拆到联盟，如 `体育·NBA`）筛选。筛选在客户端生效，切换是瞬时的；成交流水本身从不归档。
- **拆单累计榜**（`/accumulation`）——按 `(钱包, 市场, 结果)` 聚合并按**净买入**排序，抓那些用许多小单堆出大仓的钱包。每一笔计入的成交都低于单笔告警阈值，所以不会和已经触发过告警的仓位重复计数。
- **告警引擎与历史**（`/alerts`）——worker 把每次命中写进 SQLite，并可选推送 Telegram。默认值是标定出来的而不是拍脑袋：实测有 28.6% 的原始告警落在价格 ≥0.90——那是几乎已成定局的结算扫尾单、几乎不含信息量，所以 `maxPrice` 默认取 `0.95` 把这条尾巴挡在外面；另有 14.2% 的推送来自同一钱包在同一市场反复触发，所以加了 30 分钟的「同钱包同市场」冷却把它们折叠。

### 第二层 —— 谁值得盯

- **聪明钱白名单**——每日从官方盈利榜（WEEK/MONTH/ALL 合并）播种，补上已结算战绩，按可解释的 0–100 分打分（盈利 40 + 资金效率 30 + 胜率 30）。做市机器人（交易过 ≥1000 个市场）会被打 🤖 标而不是被悄悄算成「有本事」。
- **聪明钱发现**（`/discovery`）——榜单按**规模**排名，所以结构性地漏掉「小而准」的钱包。三条渠道把漏斗拓宽：成交流涌现（共识同行 · 干净拆单 · 内幕签名）、已结算市场里的早期赢家、分类榜的垂直专家。所有候选必须通过同一道**战绩准入闸**：「已结算 ≥10 个市场、胜率 ≥55% **且净盈亏为正**」**或**「已结算 ≥5 个市场且 ROI ≥5%」——刻意不用那个 0–100 评分，因为它的盈利轴会把规模偏见重新引进来。从成交流与早期赢家两条渠道浮出来的钱包，还要先满足「30 天内在 ≥3 个不同市场反复出现」才有资格被评估；分类榜专家已被自己那张榜筛过一轮，直接进战绩闸。入池后 30 天不再达标即出池。
- **钱包档案**（`/wallet/<地址>`）——当前持仓、经校验的地址年龄、已结算胜率 / ROI / 权威净盈亏、赔率带直方图、专攻品类、拆单倾向、链上闲置现金，以及本工具自己对这个钱包发过的告警历史。

### 第三层 —— 共识、分歧，以及记分

- **共识**（`/consensus`）——5 分钟一轮扫 6 小时窗口，当 ≥N 个白名单钱包各自净买 ≥$X 的同一结果时推 `🔥 聪明钱共识`。只在**形成与升级**时告警，从不重复。
- **分歧**——当聪明钱涌向一个市场的*对立*结果，朴素做法会报出两条自相矛盾的「共识」。分歧检测把它收敛成一条诚实的信号：按**质量加权的天平**（净买额 × 钱包评分），倾向 一边倒 或 势均力敌。同一钱包两边都下的对冲会被剔除（那不是真对立），且共识与分歧**互斥**——有争议的市场永远不会伪装成共识。
- **验证闭环**（📐）——每条已发告警都会在 10 分钟节奏里被回填 1h/24h 价格跟随度与最终结算结果，**不管有没有人看过它**。置信区间**按市场算而不是按告警条数算**，因为同一市场里的多条告警是同一次随机事件的多份副本。
- **策略中心**（`/follow`）——横跨 6 个 detector 族的 19 档纸面策略，其中 **6 档是反向对照**（同信号、买对面）。进场用真实 CLOB 盘口快照逐档模拟吃单，所以滑点是**执行成本**而非估算；协议 taker 手续费照收（Polymarket 并非零手续费：头部 100 个市场有 72 个开了费，占 24h 量的 57.8%）。全程零真实资金。
- **公开战绩**（`/record`）——只统计真正通过投递通道**发布过**的信号，不是全量纸面历史。每个 UTC 日已发布的信号会被哈希进一条追加式存证链，发到公开 Telegram 频道——记录一旦发出就无法事后悄悄改。

### 第四层 —— 把信号送出去

- **Telegram**——分档大单告警，带市场上下文（`占24h量 18% · 流动性 $229k · 距结算 5h`）；共识推送；每日 🩺 自检；以及一个交互式 bot：私聊丢一个市场链接给它，回你一张信号卡。投递目标在后台管理，付费实时频道与公开延迟频道推的**字段完全一样**，只差延迟。
- **信号 API**（`/api/signals`）——只吐已持久化的状态，所以消费方的突发流量永远吃不到引擎的上游预算。key 按订阅方签发（只存 sha256，可单独吊销），在**服务端**按信号类型限定范围，分 `realtime` / `delayed` 两档。出故障时降级为**字段结构完整、healthy 标 false 的空 feed**——消费方绝不会把故障误读成「今天没信号」。契约见 [`docs/api-access.md`](docs/api-access.md)，站内 `/api-docs` 渲染同一份。
- **Webhook**——面向 realtime 档 key 的 HMAC 签名推送（`X-Signature: sha256=…`），4xx 判为永久失败、5xx 重试。
- **𝕏 自动播报**——巨鲸单、共识、赛前盘点、周一报告卡图，以及对自己发过的帖在结算后自动回复战果（赢输都发）。`alerts` 表兼作发帖队列，所以 X 故障永远碰不到 Telegram 链路。

### 第五层 —— 7×24 跑起来

- **公开只读守门**——`NODE_ENV=production` 下看板对访客只读：写操作需要 `ADMIN_TOKEN`，昂贵的扇出路由按**上游请求数**而不是 HTTP 请求数限流（一次 wallet-stats 查询最多能花掉约 42 次上游调用）。用 `PUBLIC_READONLY=1|0` 强制开关。
- **运营控制台**（`/manage`）——**渲染前**就锁：令牌验证通过之前，页面上只有一个输入框，因为连 tab 标签本身都会泄露运营结构。门后是告警规则、投递目标、引擎健康度、API key、X 账号。
- **公开状态页**（`/status`）——逐循环心跳，用人话写清停跳的后果（「你会少看到什么」）。刻意不进全站导航：一盏绿灯不配占用交易者主路径上的位置。
- **抗故障**——每日 SQLite 在线备份（WAL 安全，保留最新 7 份）；任一循环停跳时 `GET /api/health` 立刻返回 503（已接进 Compose healthcheck）；可选的 `HEALTHCHECK_PING_URL` 死人开关，通过独立于本机的通道报警。

## 🧪 我们到底知道什么——以及不知道什么

大多数监控工具把信号摆给你，剩下的靠你自己脑补它有效。这个项目把体检做了，并且把结果公开，包括难看的那部分。

**体检方法。** [`scripts/edge-audit.ts`](scripts/edge-audit.ts) 用三层校正重新给每条已结算告警打分——**缺任何一层，同一份数据的结论都会翻向**：

1. **价格校准**——`edge = P(赢) − 隐含概率`。不做的话，你比的是「谁买的票更稳」而不是「谁更聪明」（老钱包均价 0.708，新钱包 0.577）。
2. **扣手续费**——用与应用同一套 `rate × p × (1−p)` 公式。中间价位约吃掉 1.2 个点，足以把任何薄 edge 变成幻觉。
3. **市场聚类**——同一市场的多条告警共享唯一结算结果，是一次随机事件的 N 份副本。不聚类会把误差低估约 1.9 倍。

**它查出了什么**（2026-08-18 那次运行）：

- **60 个受检分组，零个经得起 Bonferroni 校正**（临界 |z| = 3.34）。全样本基线净 edge `−0.87 ± 3.04`，不显著。
- **「金额大 = 聪明钱」已被证伪。** 7 个金额档全无 edge，`$200k+` 档**最差**（−5.3）。这一条没有抽样偏差，证据强。
- **「新钱包 = 内幕」是未证实，不是被证伪**——只有 22 条告警落在 12 个市场，且地址年龄只覆盖 43% 的钱包，还是非随机的。
- 信号后 1h 的价格反应对结算有很强预测力，但那是**事后信息**：按 1h 后的真实价格追涨只有 −3.9，不显著。**没有找到可交易的顺向 edge。**

**策略中心给出的是同一个答案。** 六档的线上纸面实测战绩（2026-08-13），先列三个金额驱动档：巨鲸 37% / −33.9% · 超级巨鲸 40% / −29.8% · 巨鲸精英 10% / −82%；再看另外三档——分歧解除 33% / −32.7% · 高分独狼 0% / −100% · 早期赢家跟投 48% / −18.7%，它们分别看的是分歧解除、钱包评分和早期赢家身份，与单笔金额无关。这正是那 6 个**反向对照**档存在的理由——同 detector、同参数、买对面；也是为什么「逆势少数边」（+38.9%）作为反例被保留而不是悄悄下架。

**比上面所有数字都更重要的局限。** 这份数据实际只有 **10 个有效交易日，不是 52 天**：95% 挤在 2026 年 6 月底的六天窗口里，78% 是体育（很多所谓「不同市场」其实是同一场比赛的不同盘口），而且 **2026-06-30 到 2026-08-12 断更了 43 天**，期间什么都没记录。本该抓住这次断更的停更报警当时已经写好，但还没上线。你在站上看到的任何命中率，地基就是这些。

**这对你意味着什么。** 把它当作一台**找线索去看**的仪器，而不是交易信号源。验证闭环本身是工作正常的，缺的是被验证的样本量。所有阈值都要等攒够 30 个不间断的真实交易日之后再重新标定。

## ⚡ 快速开始

### 生产部署（默认路径）—— Docker Compose

这是一个 7×24 监控：信号全天候触发，验证统计假定没有盲窗，而且——如上一节所示——一次覆盖缺口会悄无声息地毒化几个月的结论。**标准部署是一台常开的小服务器**（$5 VPS 即可），跑仓库自带的 Compose：看板 + 嵌入式引擎同容器，SQLite 挂命名卷，`restart: unless-stopped`。

```bash
git clone https://github.com/kydlikebtc/polymarket-whalewatch && cd polymarket-whalewatch
cp .env.example .env       # 可选：填 TELEGRAM_BOT_TOKEN / TELEGRAM_CHANNEL_ID
docker compose up -d --build
# 看板 → http://<服务器>:61001  （宿主机端口在 docker-compose.yml 里改）
docker compose logs -f     # 引擎心跳：[engine] starting · [consensus] window …
```

端口对公网开放之前，先在 `.env` 里设好 `ADMIN_TOKEN`——不设的话远程写入会被完全禁用，安全是安全，但你也没法从浏览器管理这个实例了。

### 本地开发

要求：**Node 22**（Docker 镜像构建与运行用的版本；`package.json` 没有声明 `engines` 下限，更老的大版本未经测试）。

```bash
npm install

npm run dev            # 看板 + 嵌入式引擎 → http://localhost:3000
npm run test           # 105 个文件共 1346 个测试，不联网，约 2 秒
npm run typecheck      # tsc --noEmit
npm run worker         # 可选：把引擎作为独立进程跑

npx tsx scripts/dry-run.ts     # 零凭证的全链路实时冒烟测试
npx tsx scripts/edge-audit.ts  # 对你自己的库重跑三层校正体检
```

### 打开 Telegram 推送

```bash
# 写进 .env：
#   TELEGRAM_BOT_TOKEN=...               （找 @BotFather 要）
#   TELEGRAM_CHANNEL_ID=@yourchannel     （bot 必须是该频道管理员）

npx tsx scripts/test-telegram.ts   # 发一条测试消息
```

两个都留空 = 只记录模式：命中依然写进 SQLite 并显示在 `/alerts`，只是不推送。

### 打开 𝕏 自动播报（可选）

只有 **app 级**密钥对是必须的；**具体哪个账号发帖**在 `/manage → 𝕏 播报账号` 里单独授权（三腿 OAuth，可授权多个账号，同时只有一个在用，切换在一个循环内生效、不用重启）。先把 `<PUBLIC_URL>/api/x-callback` 登记为该 app 的回调地址。

```bash
# 写进 .env：
#   X_API_KEY=...             # developer.x.com 上的 app（按量付费档），OAuth 1.0a
#   X_API_SECRET=...
#   X_MONTHLY_BUDGET_USD=15   # 本地 fail-closed 花费保险丝（默认 15）
#   X_MIN_TRADE_USD=50000     # 巨鲸贴门槛 —— X 配额稀缺，Telegram 不稀缺
#   X_OG_ORIGIN=http://127.0.0.1:3000   # worker 去哪儿取 /api/og/weekly
```

2026 年按量计费：纯文本帖 $0.015、带链接帖 $0.20（只有周报卡带链接），所以 $15/月 ≈ 33 帖/天。每日上限：巨鲸 20、赛前 3、结算自回复 5；共识天然稀少，不设限。建议在 X 开发者后台设同样的上限作为平台侧兜底。

全部环境变量见 [`.env.example`](.env.example)。

## 🧠 工作原理

- **上游**——Polymarket Data API（`data-api.polymarket.com`）、Gamma API（`gamma-api.polymarket.com`）、CLOB 的历史价格**与盘口快照**（`clob.polymarket.com`）、用户盈亏 API（`user-pnl-api.polymarket.com`），以及读链上闲置余额用的公共 Polygon RPC。无鉴权、无密钥、不写入。
- **扫描器取数策略**——高 `filterAmount` 的昂贵查询会超时（HTTP 408，约 5.75s），所以看板永远按**低门槛**取数，把更高的金额 / 方向 / 价格 / 年龄筛选放到客户端做。
- **地址年龄**——先用一次 `/activity?sortBy=TIMESTAMP&sortDirection=ASC` 拿到*候选*的首次活动时间，再反向回溯（最多 8 次探测）校验通过才采信。只有校验过的时间戳才永久缓存，没校验成功的会重试。
- **净盈亏（权威口径）**——取 `user-pnl?interval=1m&fidelity=1d` 累计曲线的最后一点。这正是 Polymarket 个人主页显示的那个数，并且正确地**净掉**了那些一路亏到归零的仓位。它取代了此前对 `/closed-positions` 求和的算法——那个算法按 `realizedPnl` 降序且有行数上限，等于给高频钱包喂了一份「只有赢家」的切片（曾有一个实测样本读出 +$22.96M，而真实净值是 −$6.14M）。
- **胜率 / ROI**——来自 `/closed-positions`（注意 `totalBought` 是**份额**，成本基数要算 `totalBought × avgPrice`），并合并 `/positions` 里「已结算但没平仓」的亏损仓以修正幸存者偏差。两者都最多翻 20 页 × 50 条；超出后该战绩被标 `truncated`，胜率与 ROI 会**直接不显示**（渲染成 `—`）而不是给一个错的数——被截断且按盈亏排过序的切片，真值已不可恢复，诚实的「未知」胜过自信的谎话。
- **榜单的坑（已实测）**——`rank` 返回的是字符串；每页最多 50 行；offset 翻深了会静默重发同一批行，所以按钱包去重是唯一可靠的终止条件。
- **验证**——历史价格不可变，所以跟随度只取一次并永久缓存；结算结果取自 Gamma 的已结算市场元数据，同样永不过期。
- **worker ≠ 看板**——worker 是*有状态的告警*路径（写 SQLite、推 Telegram/X）；看板是*无状态的探索*路径（直读实时 API）。两者通过 SQLite 解耦。Docker 镜像里 worker 嵌在 Next.js 进程内运行；`npm run worker` 则是独立进程。

完整的子系统拆解、数据流图、请求路径与设计约束见 **[ARCHITECTURE.md](ARCHITECTURE.md)**。

## 🗂️ 仓库结构

```
lib/            90 个模块 —— 上游客户端、告警引擎、聪明钱评分、共识/分歧、
                策略模拟、验证统计、信号总线与投递、Telegram/X 播报、运维健康
  i18n/         双语词典 + 两道测试闸（覆盖率、术语冲突）
worker/         引擎 —— 8 条循环，可嵌入 Next 或独立运行
app/            Next.js 看板：14 个页面、27 个 API 路由处理器
scripts/        dry-run · edge-audit · watch · test-telegram · issue-key
docs/           接口契约、24 份设计文档、截图  → docs/README.md
```

技术栈：TypeScript · Next.js 16 · React 19 · better-sqlite3 · zod · vitest。105 个文件共 1346 个测试，不联网、不需要 fixture 服务——几乎每个模块都是「纯函数内核 + 注入 I/O」。

状态全部落在一个 SQLite 文件里（31 张表）。其中大部分是**可重建的缓存**——删掉它，价格、年龄、市场元数据会自己重新填满。但有一部分**不可重建**：告警台账、已发布信号记录、已签发的 API key（库里只有 sha256）、已授权的 X token、投递目标，删了就永久没了。**请做备份**：引擎已经每日自动快照，但只有拷到主机之外的副本才扛得住主机本身丢失。
